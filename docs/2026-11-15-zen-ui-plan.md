# wavecode: целевой интерфейс — от философии к реализации

**Дата:** 2026-11-15 · **Ветка:** `feat/zen-ui-plan` · **Аудит-основа:** [`2026-11-15-zen-ui-audit.md`](2026-11-15-zen-ui-audit.md) · **Решение:** [`decisions/wavecode-zen-minimal-ui.yaml`](../decisions/wavecode-zen-minimal-ui.yaml) · **Макет:** [`2026-11-15-zen-ui-wireframe.html`](2026-11-15-zen-ui-wireframe.html)

Владелец поставил цель: эффективный, красивый, минималистичный интерфейс, в котором присутствует всё необходимое и ничего лишнего. Аудит показал, что сегодняшний wavecode перегружен не числом функций, а числом мест, где живёт внимание: 19 верхнеуровневых поверхностей, ~49 интерактивных регионов в дефолтном виде, три конкурирующих плавающих элемента, 25 висящих токенов и 129 hover-правил против 13 `:focus-visible`.

Этот документ — план переделки: сначала философия (почему так), потом язык (как выглядит), потом структура (как устроена навигация), потом покадровые спеки (что именно меняется), потом фазы (в каком порядке и с какими критериями).

## Часть I. Философия

### I.1. Минимализм — это экономия внимания, а не пустота

«Дзенский» интерфейс — не пустой интерфейс. Это интерфейс, в котором в каждый момент видно ровно то, что нужно для текущего действия, а всё остальное — в одном шаге от руки, но не перед глазами. Практическое следствие: мерить надо не количеством элементов, а тем, сколько внимания они забирают у человека, который пытается что-то сделать.

Отсюда три рабочих определения:

- **Фокус.** В каждый момент у экрана есть одна главная задача. Не «много функций», а одна задача, которая сейчас главная.
- **Глубина.** До любого инструмента — не больше двух шагов: рельс → лист → действие. Три уровня — сигнал, что структуру надо упрощать (Nielsen Norman Group: за пределами двух уровней раскрытия пользователи теряются).
- **Тишина.** Интерфейс не шумит сам: движение только по событию, состояние видно без тостов, анимация бесконечна только у играющего транспорта.

### I.2. Семь принципов и что им соответствует в коде

| Принцип | Смысл | Манифестация в коде |
|---|---|---|
| 1. Холст — это приложение | Музыка пишется в партитуре, не в панели настроек | Код редактора — самый крупный элемент; панели и AI — выдвижные слои поверх |
| 2. Пустота несёт структуру | Иерархия выражается расстоянием, а не рамками и свечением | Шкала `--space-*` 4/8/12/16/24/32/48; фон вместо бордеров; 3 уровня поверхности вместо 5 |
| 3. Один акцент | Цвет — смысл, а не украшение | Violet `#a78bfa` = действие; cyan = «звучит»; magenta = «пишет»; золото = только темп. Никаких glow |
| 4. Один шрифт иерархии | Типографика заменяет коробки | Geist/Inter для UI, моноширинный только для кода, чисел и нотации; размеры 11–24 px, без 9/10 px |
| 5. Состояние говорит само | Пользователь не должен гадать, что происходит | Одна зона ошибок с действием; «играет/пишет» — цветом точки; сэмплы и офлайн — в одном месте |
| 6. Инструмент под рукой, но не в лице | Полнота без перегрузки | 4 пункта рельса + один лист «Инструменты» + `⌘K`; один плавающий элемент |
| 7. Правда важнее красоты | Обещание в UI = обещание в коде | Лендинг, README и E2E-ожидания приводятся в соответствие с реальностью |

### I.3. Чего мы сознательно не делаем

- **Не прячем возможности.** Инструмент не исчезает — он уезжает в слой. Убирать возможность можно только вместе с удалением её кода.
- **Не делаем «просторнее в ущерб цели».** Пустота — ради ясности, а не ради метрики; если элемент нужен каждый день, он получает постоянное место.
- **Не тащим чужую эстетику.** «Синтвейв», «фотори», «стекло» — не цели. Цель — спокойный, плотный по смыслу, но воздушный по композиции инструмент.
- **Не переписываем всё одним коммитом.** Каждая фаза оставляет продукт работоспособным и покрыта тестом.

## Часть II. Визуальный язык Zen v1

### II.1. Палитра: оставляем «Chroma Indigo Spectrum», но меняем роль цвета

Решение по спорному вопросу: **базовую палитру не трогаем** — она уже применена в `tokens.css:1-12` и она лучше амбера (решение `wavecode-palette-rebalance` ждало выбора владельца; владелец выбрал направление «спокойно и без крика» — это и есть отказ от оранжевого alert-диапазона). Меняется не цвет, а то, как много его одновременно.

| Роль | Токен | Где применяется | Где не применяется |
|---|---|---|---|
| Основа | `--surface-0…2` (`#0a0a0e`, `#11121a`, `#181a25`) | фон, панель, приподнятый блок | — |
| Текст | `--fg`, `--fg-dim`, `--fg-ghost` | три уровня, без четвёртого | — |
| Действие | `--primary` `#a78bfa` | одна кнопка на экран, активный пункт рельса, фокус | заливка больших площадей, градиенты |
| Звучит | `--cyan` `#5eead4` | точка «играет», полоса playhead | текст, кнопки |
| Пишет | `--magenta` `#f472b6` | точка «запись» | текст, кнопки |
| Темп | `--warm` `#fbbf24` | только BPM и метроном | активные состояния, hover, свечения |
| Статус | `--ok`, `--err` | точка и текст ошибки | — |

Что удаляется: `--primary-glow`, `--cyan-glow`, `--magenta-glow`, `--warm-glow` (декоративные свечения), любые `text-shadow`/`drop-shadow` как способ показать иерархию, градиентные подложки. Что сокращается: поверхностная шкала с 5 уровней до 3 (`--surface-3/4` остаются только для тостов и модалок). Что остаётся: `--primary-soft` и `--cyan-soft` — как 14%-ные подложки активного состояния.

### II.2. Типографика, радиусы, тени, движение

- **Шрифты:** `--font-sans` (Geist/Inter) — весь UI; `--font-mono` — только код, нотация, числа, BPM. Никакого «mono-first»: код — это код, а не весь интерфейс.
- **Размеры:** 11 (подписи), 12 (мелкие контролы), 13 (обычный текст), 14 (основной), 18 (заголовки панелей), 24 (редкие акценты). Текущие `--fs-3xs: 9px` и `--fs-2xs: 10px` уходят.
- **Радиусы:** две ступени — `0` у управляющих элементов и кода, 12 px (`--radius-lg`) у карточек и листов; `--radius-pill` только у точек-статусов. Нынешние девять ступеней (4/6/8/12/16/24/pill/sheet/full) схлопываются.
- **Тени:** одна — на листах и модалках (0 24px 48px rgba(0,0,0,.45)). У кнопок, карточек и полей теней нет.
- **Движение:** длительности 120/180/240 ms, кривая `cubic-bezier(.2,.6,.2,1)`. Бесконечных анимаций — одна: playhead у играющего транспорта. Всё, что крутится без смысла (пульсы, shimmer, scanlines), удаляется. `prefers-reduced-motion` закрывает всё, включая playhead.
- **Иконки:** один набор, 20 px, штрих 1.5, `currentColor`; из уже существующего `icons.css` — он на `currentColor` и в порядке, его нужно только расширить.

### II.3. Правило «не лишнего»

Каждый новый визуальный элемент обязан пройти три вопроса: **какую задачу он обслуживает?** (если никакой — удалить), **почему он не выражается расстоянием?** (если может — это расстояние), **что он заменяет?** (если ничего — не добавлять). Это правило записывается в решение как обязательство, а измеряется guard-скриптом.

## Часть III. Структура: от 19 поверхностей к 5

### III.1. Целевая модель

```
┌──────────────────────────────────────────────────────────────┐
│ TopBar: brand ······················ undo redo share ⋯      │
├────┬─────────────────────────────────────────────┬───────────┤
│ R  │                                             │  AI       │
│ e  │                 ХОЛСТ                       │  drawer   │
│ l  │            (партитура / код)                │  (слой,   │
│ a  │                                             │  выезжает)│
│ i  │                                             │           │
│ s  │                                             │           │
├────┴─────────────────────────────────────────────┴───────────┤
│ Transport: ▶ 96 BPM 1.1.1 ·································  │
└──────────────────────────────────────────────────────────────┘
                                              ◉ Ввод (одна кнопка)
```

Пять структурных поверхностей: **холст**, **рельс**, **транспорт**, **входной док**, **лист «Инструменты»**. Всё остальное — их содержимое.

### III.2. Четыре уровня доступа

| Уровень | Что внутри | Где живёт |
|---|---|---|
| **Tier 0 — всегда** | партитура, play/stop, BPM, undo/redo, share, одна кнопка ввода | холст, транспорт, top bar, FAB |
| **Tier 1 — рельс** | Нотная · Шаги · ИИ · Ввод | вертикальный рельс (desktop) / нижний ряд (mobile) |
| **Tier 2 — лист «Инструменты»** | Пианино, Микшер, Микрофон, Визуализатор, Пресеты, Экспорт, Консоль, Настройки | один лист, 2 колонки, поиск |
| **Tier 3 — палитра команд** | всё, включая редкое и скрытое (`⌘K`) | command palette |

Глубина раскрытия — 2 (рельс → лист → действие), что укладывается в правило NN/g. Команда `⌘K` — единственный элемент, который можно назвать «экспертиза без мыши»: она решает задачу «всё доступно» без добавления кнопок.

### III.3. Реестр инструментов — архитектурный ключ

Чтобы «всё необходимое присутствует, но не перегружает» было не лозунгом, вводится один источник правды:

`ui/src/presentation/state/toolRegistry.ts` — массив записей вида `{ id, label, icon, tier, surface, shortcut, keywords }`. Из него строятся:

1. рельс (все записи `tier: 1`),
2. лист «Инструменты» (все записи `tier: 2`),
3. палитра команд (`⌘K`),
4. **e2e-тест достижимости**: для каждой записи проверяется, что из состояния покоя до неё ≤ 2 действия и что она находится в DOM.

Это превращает требование «каждый инструмент доступен» из ручной проверки в тест, который ломается, если кто-то спрячет инструмент.

### III.4. Ввод: голос и ритм — один док, два явных режима

По решению владельца ритм должен быть очевидным. Три возможных места: третья плавающая кнопка, режим внутри листа «Шаги», режим внутри входного дока.

**Выбрано: второй режим входного дока, с явным переключателем.** Обоснование:

- «Голос» и «Ритм» — это два способа *ввести* материал (речь → код, тап → код). Они принадлежат друг другу по смыслу, а не по отдельности.
- Активное решение `wavecode-voice-minimal-dock` требует ровно одну плавающую кнопку и один док. Третья FAB-кнопка из ветки `feat/rhythm-recorder` это нарушает — а значит, её логику надо взять, а кнопку не надо.
- Явный сегментированный переключатель «Голос | Ритм» делает ритм видимым: режим назван, у него свой экран, а не спрятан за вторым нажатием.
- Ритм остаётся в Tier 0/1: кнопка «Ввод» всегда на экране, первое нажатие открывает док, в доке режим переключается одним касанием.

Условие «очевидности»: в режиме «Ритм» док показывает темп, счёт и сетку нажатий — то есть ритм виден не только как вкладка, но и как рабочая поверхность.

### III.5. Инструменты-сироты: решение по каждому

| Инструмент | Где был | Решение | Куда попадает |
|---|---|---|---|
| MIDI / текстовый экспорт | `MidiIOButtons.tsx:71-193` не смонтирован | **вывести** | лист «Инструменты» → «Экспорт» |
| WAV-рендер | движок жив (`domain/services.ts:143-156`), кнопки удалены (`edad0e4`) | **вывести** | лист «Инструменты» → «Экспорт» |
| Сетка мелодии 16×36 | `MelodyGrid.tsx:111` не смонтирована | **вывести как режим** | лист «Шаги» → режим «Мелония» рядом с «Сетка» |
| `editScore` / tool-calling | `domain/tools/editScore.ts:10-32`, в запрос нет `tools` (`domain/services.ts:20-26`) | **подключить**, если прокси принимает `tools`; иначе — убрать упоминание из README | — |
| Дубль `TransportPanel` | `TransportPanel.tsx:59` не смонтирован | **удалить** | — |
| Ветка `feat/rhythm-recorder` | третья FAB + отдельная панель | **переиспользовать логику, не кнопку** | входной док, режим «Ритм» |

Правило на будущее: ни один инструмент не может остаться в состоянии «реализован, но не выведен» — это состояние запрещено реестром инструментов и e2e-проверкой.

## Часть V. План по фазам

Каждая фаза — отдельная ветка, отдельное решение в `decisions/`, отдельные критерии приёмки. Оценки — для одного разработчика, знакомого с кодовой базой.

| Фаза | Содержание | Критерий приёмки | Оценка |
|---|---|---|---|
| **0. Правда** | Переписать `docs/design.md` под фактический «Chroma Indigo Spectrum»; починить копирайт лендинга (Play, сетка, BPM, экспорт); убрать из README обещание tool-calling, если оно не подключено; починить устаревшие e2e-ожидания (`audio-recording.spec.mjs`, `mobile-sheet-push.spec.ts`, `mic-phase3.spec.mjs`) | ни одного e2e-ожидания на несуществующий UI; `docs/design.md` совпадает с `tokens.css` | 0,5–1 дн. |

| **5. Инструменты-сироты** | Вернуть MIDI и WAV-экспорт в лист; сетку мелодии — режим в «Шагах»; подключить tool-calling к прокси или убрать обещание; удалить дубль `TransportPanel`; починить черновик селектора; сделать «Создать» на лендинге валидной партитурой | ни одного инструмента в статусе «реализован, но не выведен»; первый звук с лендинга всегда валиден; черновик селектора не теряется | 3–4 дн. |
| **6. Тишина** | Диагностика и отладочная строка — за раскрытием; один регион ошибок; счётчик сэмплов и офлайн — в одном месте; один язык интерфейса (русский); тост один | дефолтный вид ≤ 20 регионов; один регион ошибок; 0 английских подписей в UI | 2–3 дн. |
| **7. Замер** | Визуальные baseline-скриншоты (desktop 1440, mobile 390), сценарий «первый звук» в e2e, замер времени до первого звука | baseline-скриншоты в репо; время до первого звука ≤ 30 с на лендинге | 1–2 дн. |

Итого ≈ 17–25 рабочих дней. Фазы 0–2 дают 70 % воспринимаемого результата (правда, чистые токены, доступность) и не ломают структуру, поэтому идут первыми.

### V.1. Что можно делать параллельно

Фаза 3 (структура) — самая рискованная, потому что трогает навигацию. Её стоит начинать только после 1 и 2, иначе придётся переделывать дважды. Фазы 0, 1, 2, 7 не конфликтуют между собой по файлам: 0 — тексты и тесты, 1 — `tokens.css`, 2 — поведение и фокус, 7 — скриншоты.

### V.2. Риски и откат

| Риск | Как проявится | Откат |
|---|---|---|
| «Инструменты пропали» после смены навигации | жалобы на исчезновение пианино/микшера | e2e-достижимость ловит до релиза; рельс и лист — оба Tier-1/Tier-2, откат — вернуть старый TabBar |
| AI-слой перекрыл партитуру | жалобы на невозможность читать код | drawer по умолчанию закрыт; по кнопке — фокус остаётся на холсте |
| Ритм-режим спутал с голосом | пользователь нажимает не туда | явный сегментированный переключатель + подпись режима в заголовке дока |
| Удаление glow и скруглений «сделало скучно» | субъективная претензия | токены остаются в `tokens.css`, откат — один коммит (фаза 1) |
| Регрессия производительности | лаги при 60 fps | замер до/после фазы 1; анимации сокращаются, а не добавляются |

## Часть VI. Принятые решения по спорным вопросам

| Вопрос | Решение | Почему |
|---|---|---|
| Палитра | Оставить Chroma Indigo Spectrum; убрать свечения и активный `--warm` | палитра уже применена и лучше амбера; менять нужно дозировку цвета, а не hue |
| Навигация | Рельс из 4 + лист «Инструменты» + `⌘K` | 4 пункта читаются без чтения, лист держит полноту, палитра даёт скорость |
| Инструменты-сироты | MIDI и WAV — в лист «Экспорт»; сетка мелодии — режим в «Шагах»; tool-calling — подключить или убрать из README | полнота без кнопочного шума; «сирота» — недопустимое состояние |
| Ритм | Второй режим входного дока, явный переключатель «Голос \| Ритм»; без третьей FAB | совпадает с решением «одна кнопка, один док»; ритм при этом остаётся на виду |
| Десктоп-навигация | Постоянный вертикальный рельс, не меню | постоянный рельс = постоянное место; меню прячет инструменты, а «скрывать» тут нельзя |

## Часть VII. Первый шаг

Начинать с фазы 0 (правда) и фазы 1 (токены) в одном спринте: они не ломают поведение, дают немедленный визуальный эффект и убирают 25 молчаливых поломок. Фаза 2 (доступность) идёт следом, потому что дешёвая по риску и обязательная по WCAG 2.2. Структурную фазу 3 запускать только после того, как визуальный язык и доступность станут нормой, — иначе структура будет переделываться дважды.
