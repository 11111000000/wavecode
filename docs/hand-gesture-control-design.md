# Техническое решение: управление музыкой жестами рук

Дата: 2026-11-15. Статус: проект решения к реализации. Целевое описание — в
[hand-gesture-control-goal.md](hand-gesture-control-goal.md); обзор вариантов и
внешние данные — в [hand-gesture-control.md](hand-gesture-control.md).

## 1. Границы решения

**Входит:** захват камеры, трекинг 21 точки кисти, признаки, сглаживание, распознавание
дискретных жестов, маппинг движений в музыкальные параметры, квантование ритмических
событий к сетке, UI включения/калибровки/превью, тесты и бенчмарк-протокол.

**Не входит:** произвольные жесты с обучением, управление нотным редактором жестами,
работа офлайн по записи, распознавание рук нескольких людей кроме как «две руки»,
вынос обработки на сервер.

**Технические ограничения проекта (проверены по коду):**

- Четыре слоя с запретами импортов (`ui/eslint.config.js`): `infrastructure` не может
  импортировать `solid-js`; `presentation` — `@strudel/*`, `@ai-sdk/*`, `idb-keyval`;
  `application` — `solid-js`, `@strudel/*`; `domain` — `solid-js`, `@strudel/*`,
  `idb-keyval`. `console` запрещён только в `domain/` и `application/`.
- Строгий TypeScript: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`,
  `verbatimModuleSyntax` (`ui/tsconfig.json`).
- Аудио — Strudel `@strudel/webaudio` + superdough 1.3.0; живой параметр темпа —
  `repl.setCps` (`ui/src/infrastructure/audio/LiveAudioEngine.ts:447-453`, `:700-716`).
- Громкость слоя меняется переписыванием текста паттерна: `injectMix` подменяет
  `.gain(X)` регуляркой (`ui/src/application/useCases/injectMix.ts:45-79`), затем
  `hotSwapPattern` пере-оценивает сниппет (`LiveAudioEngine.ts:749-757`).
- Доступных «живых» DSP-параметров сейчас нет: ни фильтров, ни `room`, ни `speed`, ни
  Strudel-`Param`. `repl.setPattern` объявлен в типах (`LiveAudioEngine.ts:156`), но не
  вызывается ни в одном месте кода (единственное упоминание — устаревший докблок
  `ui/src/domain/services.ts:64`).
- superdough умеет нужные параметры: `gain`, `postgain`, `busgain`, `room`,
  `roomfade`, `cutoff`, `lpf`, `hcutoff`, `shape` (`ui/node_modules/superdough/superdough.mjs`),
  а также модуляцию шины через `connectBusModulator`
  (`ui/node_modules/superdough/modulators.mjs:145`).
- Сетка и ритм: `getCycleProgress()` / `getCyclePosition()`
  (`LiveAudioEngine.ts:993`, `:1009`); одноразовый удар — `previewSample`
  (`ui/src/presentation/state/audioActions.ts:330`); запись нот — `appendNote` /
  `flushRec` / `commitSnippet` (`ui/src/presentation/state/pianoRecStore.ts:161/186/210`).
- Камеры в проекте нет: `getUserMedia` встречается только для микрофона, вхождений
  `video: true` в `ui/src` нет.
- Сборка: manual chunks в `ui/vite.config.ts` (`vendor-solid`, `strudel`,
  `codemirror`, `effect`), ленивые панели через `lazy(() => import(...))` +
  `<Suspense>` (`ui/src/presentation/panels/VisualizerPanelLazy.tsx`), воркеры — как
  `?worker` (`ui/src/infrastructure/audio/MicCapture.ts:4`).
- `ui/public/` сейчас содержит только иконки, манифест и сэмплы — ни wasm, ни моделей.
  CSP живёт в Caddy из другого репозитория (`~/Projects/AngaraConfig/`), и по active
  policy wavecode туда не лезет — значит, внешние origin'ы для wasm/моделей исключены.
- Деплой — только `./bin/deploy.sh` локально; PWA, офлайн-режим имеет смысл.

## 2. Архитектура

Поток данных и разрез по слоям:

```
камера ──▶ GestureCapture (infrastructure)  ──▶ HandFrame (21 точка + handedness)
                                                        │
                                                        ▼
                                        GestureFeatures (domain, чистые функции)
                                                        │
                                    ┌───────────────────┴───────────────────┐
                                    ▼                                       ▼
                       GestureControl (domain)                    GestureDetector (domain)
                   непрерывные оси + сглаживание              дискретные жесты + гистерезис
                                    └───────────────────┬───────────────────┘
                                                        ▼
                                      ControlEvent (application-типы)
                                                        │
                                   ┌────────────────────┴────────────────────┐
                                   ▼                                         ▼
                        reducer → appStore (presentation)        AudioEngine.setLiveParam
                                                                 (infrastructure → superdough)
```

Принцип: **никакой логики жестов в infrastructure и presentation**. Трекер отдаёт
точки, `domain` превращает точки в осмысленные значения, application/presentation
превращают события в вызовы движка. Благодаря этому весь жестовый слой
тестируется детерминированно, без камеры и без аудио.

## 3. Алгоритмы

### 3.1. Захват кадра

- Камера: `getUserMedia({ video: { width: 640, height: 480, frameRate: 30 } })` —
  этого достаточно MediaPipe (модель работает на 192×192/224×224 после ресайза,
  детализация выше 640×480 не даёт выигрыша в латентности, а стоит кадров).
- Режим MediaPipe: `runningMode: "VIDEO"` (в браузере асинхронного `LIVE_STREAM`
  нет) + `requestAnimationFrame`, с проверкой `video.currentTime !== lastVideoTime`:
  если предыдущий кадр ещё обрабатывается — пропускаем, берём самый свежий.
- Модель и wasm — локально: `FilesetResolver.forVisionTasks('/mediapipe/wasm')`
  (документация прямо допускает относительный путь в `modelAssetPath`), модель
  `hand_landmarker.task` из `ui/public/models/`. Внешних origin'ов нет.
- Делегат: по умолчанию `CPU`, `GPU` — только если замер на устройстве показывает
  выигрыш. В официальном бенчмарке на Pixel 6 Gesture Recognizer на GPU медленнее
  (20.87 мс против 16.76 мс), а Hand Landmarker — быстрее (12.27 против 17.12).
  Значит, delegate — измеряемый параметр, а не константа.

### 3.2. Признаки

Из 21 точки (индексы: 0 — запястье, 5/9/13/17 — MCP пальцев, 8/12/16/20 — кончики):

- `palmSize` = |P9 − P0| в нормализованных координатах кадра. Это базовая единица:
  все остальные расстояния делятся на неё, поэтому признаки не зависят от
  расстояния до камеры.
- `palmCenter` = среднее P0, P5, P9, P13, P17.
- `openness`: для каждого пальца — доля разогнутости = min(1, |P_tip − P_pip| /
  |P_mcp − P_pip|) с порогом 0.35; сумма по четырём пальцам, нормированная в 0..1.
  Большой палец — отдельно, по расстоянию P4 до P2.
- `pinch` = 1 − clamp(|P4 − P8| / (0.6 × palmSize)), 1 = соприкосновение.
- `roll` = угол вектора (P9 − P0) в плоскости кадра.
- `raised[i]` — бинарный признак пальца: для четырёх пальцев угол в суставе PIP > 160°,
  для большого — расстояние P4–P2 > 0.8 × palmSize.

### 3.3. Сглаживание (1 €)

Фильтр 1 € (Casiez et al., CHI 2012) — адаптивный: режет джиттер на медленных
движениях и почти не добавляет задержки на быстрых.

```
f_c = minCutoff + β·|dx̂|            (частота среза, Гц)
τ   = 1 / (2π·f_c)
α   = 1 / (1 + τ/dt)
x̂   = α·x + (1−α)·x̂_prev
```

Стартовые значения: `minCutoff = 1.0` Гц, `β = 0.01` (для координат), `dt` — реальная
разница между кадрами. Фильтр применяется к признакам (`palmCenterX/Y`,
`closeness`, `openness`, `pinch`, `roll`), а не к сырым точкам: дешевле и задержка
меньше. После него — deadzone ±2 % шкалы, чтобы микродвижения не дёргали параметр.

Сглаживание настраивается пользователем («чувствительность») — это параметр `minCutoff`
(0.5 — вяло/плавно, 3.0 — резко/отзывчиво).

### 3.4. Дискретные жесты

Правила (не ML — объяснимы, отлаживаются, не требуют обучения):

| Жест | Правило |
|---|---|
| `pinch` | `pinch > 0.75` (выход — `< 0.55`) |
| `openPalm` | `openness > 0.8` и ни один палец не `raised` кроме большого |
| `fist` | `openness < 0.2` |
| `pointUp` | указательный `raised`, средний/безымянный/мизинец — нет |
| `snap` | скорость сжатия `openness` > 0.8/кадр при `openness` выше 0.6 |

Гистерезис обязателен: у каждого жеста свой порог входа и порог выхода (разница
≈ 0.2), плюс **3 кадра удержания** перед выдачей события и **минимум 200 мс** между
событиями одного жеста. Это прямое следствие практики онлайн-распознавания: по
данным SHREC 2021 («Skeleton-based Hand Gesture Recognition in the Wild») системы
на скелетах заметно деградируют без такой логики.

### 3.5. Расстояние

Абсолютной глубины MediaPipe не отдаёт: `worldLandmarks` — геометрия кисти в метрах
относительно её центра, `z` в кадровых координатах отсчитывается от запястья.
Поэтому «расстояние» = **кажущийся размер кисти** `palmSize`, а «близость» =
`1 / palmSize` (обратная глубина, монотонная по дистанции).

Калибровка при первом включении: пользователь один раз показывает руку близко и
далеко; запоминаем `near` и `far` в IndexedDB, дальше шкала линейна между ними
(с нелинейным сжатием к краям, `smoothstep`). Если калибровки нет — работаем на
дефолтных значениях.

### 3.6. Маппинг в параметры

| Ось | Параметр | Кривая |
|---|---|---|
| `palmCenterY` | `pitch` | инвертированная + логарифмическая: `2^((0.5 − y) · 2)` → ±октава |
| `closeness` | `cutoff` + `room` | линейная, «ближе = ярче и мокрее» |
| `palmCenterX` | `pan` | линейная, ±1 |
| `roll` | `speed`/`cutoff` | линейная, центр = исходное значение |
| `openness` | `volume` | опционально: раскрытая ладонь = громче |

Все значения нормализованы в 0..1 и переводятся в конкретные единицы в `mapping.ts`
(целочисленные MIDI-ноты для `pitch`, линейный gain 0..1.5 для `volume`,
log-частоты 200..12000 Гц для `cutoff`).

### 3.7. Ритм: квантование к сетке

Жест не «бьёт там, где пришёл»: суммарная задержка 70–120 мс означает, что попадание
в сетку плавало бы на десятки миллисекунд. Поэтому событие планируется:

1. По `getCycleProgress()` и текущему `cps` вычисляется позиция в цикле.
2. Ищется ближайшая доля (по умолчанию 1/4) **не раньше** `now + lookahead`
   (120 мс), иначе — следующая.
3. Если до ближайшей доли меньше lookahead — событие переносится вперёд (а не
   опаздывает): бить «вдогонку» хуже, чем чуть позже.

Точность триггера упирается в точность `getCycleProgress()` — её и надо проверить в
фазе 1 отдельным замером.

### 3.8. Потеря трекинга и отпускание

- 1–2 кадра без руки → параметры замораживаются на последнем значении.
- Нет руки дольше 1.5 с → «отпускание»: параметры плавно (300 мс) возвращаются к
  нейтрали, а не прыгают в ноль.
- Трекер теряет руку в тёмноте и при контровом свете — это ожидаемое поведение, и
  приложение обязано вести себя именно так, а не «дёргать» звук.

### 3.9. Бюджет задержки

| Участок | Задержка |
|---|---|
| Очередь кадра камеры (30 fps) | ~33 мс |
| `detectForVideo` (замер на Pixel 6) | 12–17 мс |
| Фильтр 1 € | 20–40 мс |
| Маппинг и вызов параметра | < 1 мс |
| Рэмп Web Audio | 20–50 мс (по настройке) |
| **Итого** | **70–130 мс** |

Для непрерывных параметров это незаметно; для ритмических событий — критично,
поэтому они квантуются (3.7).

## 4. Расширение аудио-движка (блокирующая часть)

Без живого DSP-пути непрерывное управление невозможно: единственный существующий
путь (`injectMix` → `hotSwapPattern`) переписывает текст паттерна и пере-оценивает
его, что на каждый кадр означает пересборку паттерна, риск рассинхронизации сетки и
щелчки на стыках.

Целевой контракт — `AudioEngine.setLiveParam(LiveParam)`. Две реализации на выбор,
обе требуют отдельной разведки в фазе 0:

**Вариант A — напрямую в superdough (рекомендуемый).** superdough уже держит
`AudioParam` нод (`gain`, `cutoff`, `room` и т.д.) и умеет модуляцию шины
(`connectBusModulator`, `superdough/modulators.mjs:145`). Нужен доступ к живым нодам:
разобраться с `getSuperdoughAudioController()` (он уже используется в
`ui/src/infrastructure/audio/AudioRecorder.ts`) и с `nodeTracker`. После этого
значение пишется через `param.setTargetAtTime(value, ctx.currentTime, timeConstant)`
— это даёт ровно то «ведение» параметра, ради которого всё затевалось, и не даёт
щелчков.

**Вариант B — через Strudel `Param`/`.set()`.** Если в текущей версии Strudel
поддерживается изменение параметра без пере-оценки паттерна, это чище
декларативно. Проверить наличие и поведение нужно отдельно: в текущем коде
`setPattern` только объявлен (`LiveAudioEngine.ts:156`) и ни разу не вызывается.

**Приёмка фазы 0 (DoD):**
- Значение параметра меняется на работающем паттерне **без** пере-оценки паттерна
  (проверяется тестом: счётчик `repl.evaluate` не растёт).
- Нет щелчков: измеренный выход — непрерывный (тест «шаг значения не даёт скачка»).
- Параметр сбрасывается к нейтрали при выключении панели.
- Работает при переключении слоя/соло/мьюта без «залипания» на старом слое.

Пока это не сделано, фазы 1–3 начинать бессмысленно.

## 6. UI

Панель «Руки» (bottom-sheet, по образцу `MicPanel`):

- тумблер «Управление руками» (включение = запрос камеры);
- превью 160×120 с оверлеем: 21 точка, контур кисти, текущий жест, значения осей;
- калибровка «близко/далеко» (кнопки, видно прогресс);
- маппинг: список осей с выбором «выключено / громкость / высота / фильтр / панорама»,
  инверсия, «чувствительность» (minCutoff фильтра);
- переключатель «две руки»;
- индикатор трекинга: «рука потеряна» / «идёт калибровка» / «готов».

Превью сворачивается в маленький бейдж; управление продолжает работать без него.

## 7. Тесты

**Юнит-тесты `domain/gesture/` (главные):** фильтр 1 € (шум → меньше разброса,
быстрый скачок → задержка в пределах бюджета), признаки на фикстурах из реальных
landmark-ов, правила жестов и гистерезис (в т.ч. что «мерцание» не выдаёт событий),
кривые маппинга (монотонность, дедзона), квантование (событие всегда попадает в
долю, никогда не в прошлое).

Фикстуры landmark-ов снимаются один раз в реальной сессии и кладутся в
`ui/src/domain/gesture/fixtures/` — это делает тесты воспроизводимыми.

**Интеграционные:** фейковый `GestureCapture` (скрипт landmark-ов) →
события → `reducer` → вызовы `AudioEngine` (мок) — проверяется, что «щипок» даёт
ровно один `discrete`-событие, а движение ладони — `continuous` с монотонным
значением.

**E2E (Playwright):** Chromium с фейковой камерой (`--use-fake-device-for-media-stream`
и `--use-file-for-fake-video-capture=<file.y4m>`) — можно прогонять заранее
записанное видео с рукой без физической камеры. Требует проверки на текущей версии
Playwright/Chromium, но механизм штатный.

**Приватность:** тест, что при включённой камере нет сетевых запросов к внешним
origin'ам (перехват запросов в Playwright) — кроме уже существующих обращений к
LLM-прокси.

## 8. Бенчмарк-протокол

Скрипт `scripts/bench/hand-latency.ts` (в браузере, через vite dev) на целевых
устройствах:

1. 200 кадров с рукой — измеряем p50/p95 времени `detectForVideo` отдельно для
   `delegate: CPU` и `GPU`.
2. Задержка «жест → изменение параметра»: кадр с меткой времени + чтение
   `AudioParam` в следующем цикле рендера.
3. Ложные срабатывания: 10 минут свободного движения рукой без намерения →
   число дискретных событий.
4. Время до первого результата (старт трекера, прогрев wasm).

Пороги приёмки: p95 инференса < 25 мс, сквозная задержка < 130 мс, ложных
срабатываний < 1/мин, старт трекера < 3 с после включения.

## 9. Фазы

| Фаза | Содержание | DoD |
|---|---|---|
| **0. Живой DSP-путь** | `AudioEngine.setLiveParam`, реализация A или B | Значение меняется без пере-оценки паттерна, без щелчков, есть тест |
| **1. MVP-трекер** | Камера, HandLandmarker, оверлей, сглаживание, 2 непрерывные оси (высота, накал) | p95 < 25 мс, сквозная < 130 мс, 20 мин без залипаний |
| **2. Ритм** | Квантование к сетке, щипок → удар, проверка точности `getCycleProgress` | Удар попадает в долю, дрейф < 20 мс на 5 минут |
| **3. Жесты и полировка** | Правила жестов, гистерезис, калибровка, две руки, UI маппинга | Ложных срабатываний < 1/мин, калибровка работает |
| **4. Терминовка** | Режим записи ритма руками → заполнение сетки | Ритм из 8 ударов превращается в сетку без правок вручную |
| **5. Обучаемые жесты** (опционально) | Дообучение классификатора на пользовательских жестах | Новый жест распознаётся после 30–50 примеров |

Каждая фаза — отдельная ветка с тестами; откат = откат ветки, данные не мигрируют.

## 10. Риски

| Риск | Митигация |
|---|---|
| Нет живого DSP-пути → нечем управлять | Фаза 0 первая, с тестом |
| Тёмный свет / контровой свет → потеря руки | Freeze вместо сброса, индикатор «рука потеряна» |
| Джиттер → «музыкальные» скачки | 1 € фильтр + deadzone + гистерезис |
| Ритм промахивается | Квантование к сетке, а не «как пришло» |
| Тяжёлый wasm бьёт по старту приложения | Ленивый чанк + ленивый импорт + локальные модели |
| Safari/старые браузеры | Fallback на `delegate: CPU`, feature-detect; при несовместимости — кнопка отключена с объяснением |
| Приватность | Кадры не покидают браузер; тест на сетевые запросы; текст в UI |
| Гейт math-coding неработоспособен (ядро 3.7 удалено upstream, CI ставит edge → 404) | Решение фиксировать в том формате, который реально проверяется (mathc v5 / `spec.json`), либо починить гейт — на усмотрение владельца |

## 11. Открытые вопросы

1. **Формат фиксации решения** — mathc v5 (`spec.json`) или восстановление гейта 3.7.
2. **Первый набор жестов** — предлагается щипок/ладонь/кулак/указание вверх.
3. **Первая непрерывная ось для MVP** — предлагается высота (самая «музыкальная»).
4. **Режим терминовки** — входит ли в MVP или в отдельную фазу 4.
